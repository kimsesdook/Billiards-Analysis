# Billiards Analysis v1.0.0

- Release date: 2026-08-17
- Release type: Initial portfolio release
- Runtime: Java 17, Node.js 22, MySQL 8.4, Redis 7.4
- Deployment status: Local Docker and CI validated; production cloud deployment deferred

## Summary

`v1.0.0` is the first complete release of Billiards Analysis. It turns personal billiards records into member-scoped statistics, weekly comparisons, opponent history, realtime game-room scoring, and optional aggregate-only AI coaching. The release emphasizes authorization, transactional consistency, safe distributed coordination, observability, and repeatable automated verification.

## Highlights

- Complete account and refresh-session lifecycle with JWT access authentication.
- Game-record CRUD, search, pagination, trends, weekly reports, and opponent statistics.
- Friend requests, match invitations, persisted notifications, and administrator workflows.
- Two-user realtime game rooms with ready/start events, versioned score state, transactional finish, and generated records.
- Optional Gemini report generation protected by cache, distributed lock, rate limit, timeout, circuit breaker, and bounded concurrency.
- Three authenticated, read-only MCP tools verified through the official MCP protocol client.
- MySQL, Redis, Flyway, Docker Compose, Actuator, Micrometer, OpenTelemetry, k6, Playwright, ArchUnit, JaCoCo, and GitHub Actions.

## Run Locally

```powershell
docker compose up -d --build
```

Verify readiness:

```powershell
Invoke-RestMethod http://localhost:8080/actuator/health/readiness
Invoke-WebRequest http://localhost:3000
```

The frontend is available at `http://localhost:3000`, Swagger UI at `http://localhost:8080/swagger-ui.html`, and public build metadata at `http://localhost:8080/actuator/info`.

## Upgrade And Data

- The backend and frontend artifact versions are `1.0.0`.
- Existing local MySQL volumes are migrated automatically through Flyway V1-V17.
- Applied migration files must not be edited; later schema changes require a new migration.
- `docker compose down` preserves the named MySQL volume. Do not add `--volumes` unless the local data is disposable.

## Security And Cost Defaults

- Real secrets remain outside Git and frontend bundles.
- `AI_CHAT_MODEL=none`, `MCP_ENABLED=false`, and OTLP export disabled are the defaults.
- MCP does not call a model and requires no provider key.
- No cloud resource is provisioned and no paid external coverage or observability service is required.

## Known Limitations

- Production deployment, TLS termination, protected metrics collection, backup policy, and restore testing remain environment decisions.
- WebSocket broadcast is process-local and needs sticky sessions or a message broker for multi-instance delivery.
- Gemini integration is implemented but this release does not claim a real provider call.
- Global operator-driven refresh-session revocation is documented as a pre-production operational gap.
